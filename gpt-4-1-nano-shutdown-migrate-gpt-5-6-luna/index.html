gpt-4.1-nano 下线后换 gpt-5.6-luna：只改模型名还不够

OpenAI 弃用页（Deprecations）在 2026-04-22 的旧版 GPT 快照条目里列出：gpt-4.1-nano 和 gpt-4.1-nano-2025-04-14 于 2026 年 10 月 23 日下线，推荐替代模型是 gpt-5.6-luna。如果你的分类、抽取、路由类调用最近开始失败，先查代码里是不是还在用这两个名字。gpt-5.6-luna 是推理模型，不写推理强度时默认按 medium 推理，输出上限也把推理 token 算在内，所以只把 model 字段换掉，可能变慢、变贵，或者拿到空输出。本页根据官方弃用页、gpt-5.6-luna 模型页、推理指南和 Chat Completions 接口参考，列出要改的地方和改完怎么验证。

gpt-4.1-nano 什么时候下线，官方让换成什么？

官方弃用页（https://developers.openai.com/api/docs/deprecations）2026-04-22「Legacy GPT model snapshots」条目的表格里，gpt-4.1-nano 与 gpt-4.1-nano-2025-04-14 的替代模型写的是 gpt-5.6-luna，下线日期是 2026 年 10 月 23 日。同一条目下注明，这些模型的微调版本与对应的基础模型按同一时间表下线。

弃用页对下线的说明是：到了下线日期，模型或端点将不再可以访问。页面没有写明下线后请求会返回哪个错误码，所以不要只靠某一种报错文字判断，应直接在代码和配置里搜索 gpt-4.1-nano 这两个名字。

要用程序确认某个模型有没有下线日期，可以调用 List models（GET /v1/models）或 Retrieve a model，查看 shutdown_date 字段：有值时是 YYYY-MM-DD 格式的日期，没有公布下线日期时为 null。弃用页还提到，部分情况下开发者可以联系销售，通过专用容量在下线日期之后继续访问。

另外，同一页 2026-06-11 的条目里，gpt-5-nano（gpt-5-nano-2025-08-07）的替代模型也是 gpt-5.6-luna，下线日期为 2026-12-11。两个 nano 都在用的项目，可以按本页的步骤一次迁完。

只改模型名会出什么问题：推理强度默认变成 medium

gpt-5.6-luna 模型页（https://developers.openai.com/api/docs/models/gpt-5.6-luna）写明它是面向成本敏感、高并发场景的 GPT-5.6 模型，大致对应早期 GPT-5 系列的 nano 档；reasoning.effort 可选 none、low、medium（默认）、high、xhigh、max。推理指南（https://developers.openai.com/api/docs/guides/reasoning）也写明：不写 reasoning.effort 时，GPT-5.6 默认 medium。

gpt-4.1-nano 的老代码里通常没有推理强度参数。换成 gpt-5.6-luna 后如果还不写，每次请求都会按 medium 推理，耗时和 token 用量都可能比原来多，这对原来追求低延迟、大批量的 nano 流程影响最大。

官方给的选择依据：推理指南把 none 描述为适合不需要推理、也没有多步工具调用的延迟敏感任务；GPT-5.6 升级指南（https://developers.openai.com/api/docs/guides/upgrading-to-gpt-5p6-sol）建议把 medium 作为均衡的起点，延迟敏感的任务用 low，如果用 none，就把它作为延迟基准，并在任务能从推理或工具调用中获益时再测一下 low。high、xhigh 等评测证明能提升质量时再用，max 留给最难、质量优先的任务。

写法上，Responses API 用 "reasoning": {"effort": "none"}，Chat Completions 用 "reasoning_effort": "none"。建议在迁移的第一版里显式写出推理强度，不要依赖默认值。

max_tokens 要改成什么，输出上限为什么要留大一点？

Chat Completions 接口参考（https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create）写明：max_tokens 已弃用，改用 max_completion_tokens，并且 max_tokens 与 o 系列模型不兼容。max_completion_tokens 是可生成 token 数的上限，包含可见输出 token 和推理 token。旧代码里如果还写着 max_tokens，迁移时一起换成 max_completion_tokens。

因为推理 token 也计入上限，原来给 nano 设的很小的输出上限（只够放一个标签或一小段 JSON）换到 gpt-5.6-luna 后可能不够用。推理指南对 Responses API 的说明是：生成的 token 达到上下文上限或 max_output_tokens 时，响应 status 为 incomplete，incomplete_details.reason 为 max_output_tokens，而且可能在产生任何可见输出之前就发生，这时输入和推理 token 照样计费，却拿不到可见回答。

官方建议刚开始试用推理模型时，为推理和输出至少预留 25,000 个 token，熟悉实际推理用量后再调整。把推理强度设为 none 或 low 的流程，也要用真实输入检查一次输出是否完整，不要沿用旧上限后不做检查。

模型页列出的规格是上下文窗口 1,050,000 个 token、最大输出 128,000 个 token，输入支持文本和图片，输出只有文本。

temperature 等参数、接口和功能还能照用吗？

接口方面，模型页列出 gpt-5.6-luna 支持 Chat Completions（v1/chat/completions）、Responses（v1/responses）和 Batch（v1/batch），所以原来走 Chat Completions 或 Batch 的 nano 调用不必为了换模型而换接口。推理指南同时说明，推理模型配合 Responses API 效果更好，Chat Completions 仍然支持；升级指南建议推理、工具调用和多轮对话用 Responses API。

功能方面，模型页把流式输出、函数调用、结构化输出标为支持，Fine-tuning 标为不支持；网页搜索、文件检索、代码解释器、MCP 等工具列在「使用 Responses API 时支持的工具」下。音频、视频模态不支持，Embeddings、Realtime 和语音相关端点也不在支持之列，原来顺带用 nano 做这些事的，需要另选模型。

采样参数方面，官方 GPT-5.6 升级说明没有逐项列出 temperature、top_p、logprobs 的兼容规则。旧请求里带着这些参数的，先用一条保留原参数的请求测试；如果被拒绝，按返回的错误信息里指出的参数调整，不要一次删掉一批参数来让请求跑通，也不要凭猜测改写。

多轮对话方面，升级指南说明 GPT-5.6 默认 reasoning.context 为 all_turns，会把之前轮次可用的推理带入下一轮，更早的模型默认 current_turn。自己管理对话历史时，要原样回传之前的用户输入和每一个响应输出项。

微调过的 gpt-4.1-nano 怎么办？

弃用页写明，这批模型的微调版本与基础模型同一天下线，也就是基于 gpt-4.1-nano 微调出的模型同样在 2026-10-23 停用。

gpt-5.6-luna 模型页的 Fine-tuning 一项标为不支持，所以不能把原来的训练数据直接拿去在 gpt-5.6-luna 上再微调一个替代品。

可行的做法是：把微调想达到的效果（固定输出格式、领域术语、分类标准）改成提示词里的说明和少量示例，必要时配合结构化输出约束格式，再用原来的评测集比较新旧结果；如果评测达不到要求、业务又必须继续用原模型，按弃用页的说法联系 OpenAI 销售了解专用容量。

迁移步骤和怎么确认改好了

第一步，盘点：在代码、环境变量、配置文件、模型白名单、计费或价格元数据、测试用例里搜索 gpt-4.1-nano 和 gpt-4.1-nano-2025-04-14，同时搜一下 gpt-5-nano，它在 2026-12-11 下线，替代模型同样是 gpt-5.6-luna。

第二步，改请求：model 改为 gpt-5.6-luna；显式写推理强度（低延迟流程先用 none 作基准，再对比 low）；max_tokens 换成 max_completion_tokens，并把上限调到能容纳推理 token 的水平。

第三步，对比测试：拿一批有代表性的真实输入，分别测试 none 和 low（或 medium），记录任务正确率、结构化输出能否解析、首字延迟和总耗时，以及响应 usage 里的输入、输出、推理和缓存 token。

成功标准：代码里已经没有调用 gpt-4.1-nano 的地方；新请求返回的 model 字段是 gpt-5.6-luna；没有因为输出上限出现空回答或回答被截断；正确率和解析成功率不低于旧模型；每个成功任务的耗时和 token 用量在可接受范围内。还没验证到的场景要单独记下来，不要因为模型名已经改完就当作迁移结束。

通过中转服务调用 gpt-5.6-luna 要注意什么？

先调用中转服务的 /v1/models，确认列表里有 gpt-5.6-luna，并以列表里的模型名为准。

再发一条带推理强度参数（Chat Completions 的 reasoning_effort 或 Responses 的 reasoning.effort）和输出上限参数（Chat Completions 的 max_completion_tokens 或 Responses 的 max_output_tokens）的最小请求，确认参数被原样传给上游：看返回的 model 字段和 usage 里的推理 token 是否符合预期。

价格方面，gpt-5.6-luna 的单价、缓存和长输入的计费规则以官网价格页为准；通过中转调用时，以平台价格页展示的为准。
